# D3D11_TEXTURE2D_DESC

一句话直觉：`D3D11_TEXTURE2D_DESC` 是创建 `ID3D11Texture2D` 前填写的一张“规格表”。它告诉 D3D11：这张 texture 多大、什么格式、怎么用、能不能作为 render target / depth buffer / shader resource。

它本身不是 GPU 资源，只是一个 CPU 侧的描述结构。真正的 texture 是后面 `CreateTexture2D` 创建出来的 `ID3D11Texture2D`。

---

## 基本用法

```cpp
D3D11_TEXTURE2D_DESC desc = {};
desc.Width = 1920;
desc.Height = 1080;
desc.MipLevels = 1;
desc.ArraySize = 1;
desc.Format = DXGI_FORMAT_R8G8B8A8_UNORM;
desc.SampleDesc.Count = 1;
desc.SampleDesc.Quality = 0;
desc.Usage = D3D11_USAGE_DEFAULT;
desc.BindFlags = D3D11_BIND_RENDER_TARGET | D3D11_BIND_SHADER_RESOURCE;
device->CreateTexture2D(&desc, nullptr, &texture);
```

常见读法：

```text
先描述 texture 要长什么样
再把 descriptor 交给 device
device 根据 descriptor 创建真正的 GPU texture
```

---

## 为什么先清零

```cpp
D3D11_TEXTURE2D_DESC desc = {};
```

`D3D11_TEXTURE2D_DESC` 是一个 C++ struct。创建某种 texture 时，通常只手动填写其中一部分字段。

用 `= {}` 初始化的作用是：**把整个 descriptor 的所有字段先变成 0**。这样没手动填写的字段也有确定的默认值，而不是随机内存垃圾值。

例如这些字段经常不会每次都显式填写：

```cpp
desc.CPUAccessFlags;
desc.MiscFlags;
desc.SampleDesc.Quality;
```

如果写成这样：

```cpp
D3D11_TEXTURE2D_DESC desc;
```

未填写字段不会自动清零，可能残留随机值。D3D11 可能误以为 texture 需要 CPU 访问、有特殊资源标记，或者使用非法的 MSAA quality，最后导致 `CreateTexture2D` 失败。

> [!tip]
> D3D11 descriptor 常见写法都是先清零，再填写自己关心的字段。这样 descriptor 的状态是确定的，排查问题也更容易。

---

## 字段解释

```cpp
// Width in texels
desc.Width = 1920;

// Height in texels
desc.Height = 1080;

// Number of mipmap levels; use 1 when no mipmaps are needed
desc.MipLevels = 1;

// Number of textures in the array; use 1 for a normal single texture
desc.ArraySize = 1;

// Pixel format; decides channel layout, precision, and interpretation
desc.Format = DXGI_FORMAT_R8G8B8A8_UNORM;

// MSAA sample count; use 1 for no MSAA
desc.SampleDesc.Count = 1;

// MSAA quality level; use 0 for the default quality level
desc.SampleDesc.Quality = 0;

// GPU/CPU usage pattern
desc.Usage = D3D11_USAGE_DEFAULT;

// How the texture can be bound to the pipeline
desc.BindFlags = D3D11_BIND_RENDER_TARGET | D3D11_BIND_SHADER_RESOURCE;

// CPU access permission; usually 0 for GPU-only textures
desc.CPUAccessFlags = 0;

// Optional flags for special texture behavior
desc.MiscFlags = 0;
```

## `MipLevels`

`MipLevels` 表示这张 texture 有多少个 mipmap 层级。

```text
Level 0: 原始尺寸
Level 1: 1/2 尺寸
Level 2: 1/4 尺寸
...
```

普通 render target、backbuffer、depth buffer 通常不需要 mipmap，所以写：

```cpp
desc.MipLevels = 1;
```

如果是给 shader 采样的普通贴图，并且需要远处采样更稳定，才会考虑多个 mip levels。

```cpp
// Special value: create the full mipmap chain based on texture size
desc.MipLevels = 0;

// GenerateMips needs SRV for reading and RTV for writing generated mip levels
desc.BindFlags = D3D11_BIND_SHADER_RESOURCE | D3D11_BIND_RENDER_TARGET;

// Allow the GPU to generate mipmaps later
desc.MiscFlags = D3D11_RESOURCE_MISC_GENERATE_MIPS;
```

`MipLevels = 0` 是 D3D11 的特殊写法，意思不是“没有 mipmap”，而是让 D3D11 根据 texture 尺寸创建完整 mipmap chain。这组设置常用于从 image 创建 shader texture。

典型流程：

```text
1. Create texture with full mip chain
2. Upload image data into level 0
3. Create SRV
4. Call GenerateMips(srv)
5. GPU generates level 1, level 2, level 3...
```

## `SampleDesc`

`SampleDesc` 控制 texture 的 multisampling 设置，也就是 MSAA 相关设置。

```cpp
desc.SampleDesc.Count = 1;
desc.SampleDesc.Quality = 0;
```

`Count` 表示每个像素有几个 sample：

```text
Count = 1 -> no MSAA
Count = 2 -> 2x MSAA
Count = 4 -> 4x MSAA
Count = 8 -> 8x MSAA
```

MSAA 是 **Multisample Anti-Aliasing**。它的核心思路是：一个像素内部放多个 sample point，分别判断这些 sample 是否被三角形覆盖，最后混合成这个像素的颜色。

不开 MSAA 时：

```text
每个像素 1 个 sample
边缘更容易出现 stair-step aliasing
```

4x MSAA 时：

```text
每个像素 4 个 sample
边缘像素可以表达部分覆盖
模型边缘更平滑
显存、带宽、性能开销更高
```

`Quality` 表示当前 sample count 下使用哪一种 sample pattern / quality level。

普通不开 MSAA 时，最常见写法是：

```cpp
desc.SampleDesc.Count = 1;
desc.SampleDesc.Quality = 0;
```

如果要开 MSAA，不能随便填 `Quality`。通常先查询 device 支持多少 quality levels：

```cpp
UINT qualityLevels = 0;
device->CheckMultisampleQualityLevels(desc.Format, 4, &qualityLevels);
```

如果 `qualityLevels > 0`，合法的 quality 值通常是：

```text
0 到 qualityLevels - 1
```

> [!warning]
> 同一个 render pass 里绑定的 render target 和 depth buffer，`SampleDesc.Count` 通常必须匹配。例如 render target 是 4x MSAA，depth buffer 也要是 4x MSAA。

## `Format`

`Format` 决定每个像素怎么存数据。

```cpp
desc.Format = DXGI_FORMAT_R8G8B8A8_UNORM;
```

常见格式：

| 格式 | 每像素布局 | 常见用途 |
| :--- | :--- | :--- |
| `DXGI_FORMAT_R8G8B8A8_UNORM` | RGBA，每通道 8-bit UNORM | 普通颜色 |
| `DXGI_FORMAT_R16G16B16A16_FLOAT` | RGBA，每通道 16-bit float | HDR、GBuffer 中间数据 |
| `DXGI_FORMAT_D24_UNORM_S8_UINT` | 24-bit depth + 8-bit stencil | Depth-stencil buffer |
| `DXGI_FORMAT_R32_FLOAT` | 单通道 32-bit float | 精确数值、深度数据 |

详见 [[rendering/Render-Target]] 和 [[D3D11.DepthBuffer]]。

---

## `Usage`

`Usage` 描述资源的 CPU/GPU 使用模式：谁会读、谁会写、CPU 是否需要直接访问。

```cpp
desc.Usage = D3D11_USAGE_DEFAULT;
```

`D3D11_USAGE_DEFAULT` 是最常见的 GPU resource 用法：

```text
GPU can read
GPU can write
CPU cannot directly map/read/write
```

对 render target、depth buffer、普通 GPU texture 来说，通常都用：

```cpp
desc.Usage = D3D11_USAGE_DEFAULT;
```

因为这些资源主要在 GPU 内部流转：

```text
Render target: GPU writes color, later GPU shader may read it
Depth buffer: GPU writes depth, GPU reads it during depth test
```

常见 `Usage`：

| Usage | 含义 | 常见用途 |
| :--- | :--- | :--- |
| `D3D11_USAGE_DEFAULT` | GPU 正常读写，CPU 不直接访问 | render target、depth buffer、GPU texture |
| `D3D11_USAGE_IMMUTABLE` | 创建后不再改变 | 永远不变的 texture / buffer |
| `D3D11_USAGE_DYNAMIC` | CPU 经常更新，GPU 读取 | 每帧更新的 constant buffer / dynamic vertex buffer |
| `D3D11_USAGE_STAGING` | CPU 读写用的中转资源 | readback、截图、debug dump |

---

## `BindFlags`

`BindFlags` 决定这张 texture 可以用在管线的哪个位置。

```cpp
desc.BindFlags = D3D11_BIND_RENDER_TARGET;
```

常见组合：

| Bind flag | 意义 |
| :--- | :--- |
| `D3D11_BIND_RENDER_TARGET` | 可以创建 RTV，被 GPU 写入颜色 |
| `D3D11_BIND_SHADER_RESOURCE` | 可以创建 SRV，被 shader 采样读取 |
| `D3D11_BIND_DEPTH_STENCIL` | 可以创建 DSV，用于 depth/stencil test |
| `D3D11_BIND_UNORDERED_ACCESS` | 可以创建 UAV，用于 unordered read/write |

同一张 texture 可以有多种用途，但不能在同一时间以冲突方式读写。例如同一资源不能同时作为 RTV 写入又作为 SRV 读取。

例如：

```cpp
desc.BindFlags = D3D11_BIND_RENDER_TARGET | D3D11_BIND_SHADER_RESOURCE;
```

表示这张 texture 既可以创建 `ID3D11RenderTargetView` 被 GPU 写入，也可以创建 `ID3D11ShaderResourceView` 被 shader 采样读取。

常见场景是后处理：

```text
Pass 1: scene -> off-screen render target
Pass 2: off-screen texture -> shader resource -> bloom / tone mapping / blur
```

注意：同一张 texture 不能同一时间一边作为 RTV 写，一边作为 SRV 读。要先解绑 RTV，再绑定 SRV。

---

## `CPUAccessFlags`

`CPUAccessFlags` 控制 CPU 是否能直接访问这张 resource。

```cpp
desc.CPUAccessFlags = 0;
```

`0` 表示 CPU 不直接读写这张 texture。对 render target、depth buffer、普通 GPU texture 来说，这是最常见设置。

常见值：

| CPU access flag | 含义 |
| :--- | :--- |
| `0` | CPU 不直接访问 |
| `D3D11_CPU_ACCESS_READ` | CPU 可以读取 |
| `D3D11_CPU_ACCESS_WRITE` | CPU 可以写入 |

如果要从 GPU texture 读回 CPU，例如截图或 debug dump，通常不会直接让 render target CPU-readable，而是创建 staging resource：

```cpp
stagingDesc.Usage = D3D11_USAGE_STAGING;
stagingDesc.CPUAccessFlags = D3D11_CPU_ACCESS_READ;
stagingDesc.BindFlags = 0;
context->CopyResource(stagingTexture, gpuTexture);
```

---

## `MiscFlags`

`MiscFlags` 是 miscellaneous flags，用来开启额外特殊行为。

```cpp
desc.MiscFlags = 0;
```

`0` 表示这是一张普通 texture，不启用特殊功能。

普通 render target、depth buffer、常规 texture 通常都写：

```cpp
desc.MiscFlags = 0;
```

什么时候不是 `0`：

| Misc flag | 含义 |
| :--- | :--- |
| `D3D11_RESOURCE_MISC_GENERATE_MIPS` | 允许 GPU 自动生成 mipmap |
| `D3D11_RESOURCE_MISC_TEXTURECUBE` | 把 texture array 当作 cubemap |
| `D3D11_RESOURCE_MISC_SHARED` | 允许资源共享 |

所以 `desc.MiscFlags = 0;` 的意思是：

```text
No generate mips
Not a cubemap
Not shared
No special resource behavior
```

```cpp
// Allow the GPU to generate mipmaps for this texture
desc.MiscFlags = D3D11_RESOURCE_MISC_GENERATE_MIPS;

// Required companion setup for GenerateMips
desc.MipLevels = 0;
desc.BindFlags = D3D11_BIND_SHADER_RESOURCE | D3D11_BIND_RENDER_TARGET;

// Generate the mip chain from level 0
m_deviceContext->GenerateMips(shaderResourceView);
```

`D3D11_RESOURCE_MISC_GENERATE_MIPS` 表示这张 texture 允许 GPU 自动生成 mipmaps。普通 render target / depth buffer 不需要这个 flag；普通图片 texture 如果要支持 mipmap，才会用它。

## Depth Buffer 示例

```cpp
D3D11_TEXTURE2D_DESC depthDesc = {};
depthDesc.Width = g_engine->m_window->GetClientDimensions().x;
depthDesc.Height = g_engine->m_window->GetClientDimensions().y;
depthDesc.MipLevels = 1;
depthDesc.ArraySize = 1;
depthDesc.Usage = D3D11_USAGE_DEFAULT;
depthDesc.Format = DXGI_FORMAT_D24_UNORM_S8_UINT;
depthDesc.BindFlags = D3D11_BIND_DEPTH_STENCIL;
depthDesc.SampleDesc.Count = 1;
depthDesc.SampleDesc.Quality = 0;
device->CreateTexture2D(&depthDesc, nullptr, &depthStencilTexture);
```

这里 `D3D11_TEXTURE2D_DESC` 描述的是一张 depth-stencil texture。创建完成后，通常还要基于它创建 `ID3D11DepthStencilView`，见 [[D3D11.DepthBuffer]]。

## Render Target 示例

```cpp
D3D11_TEXTURE2D_DESC rtDesc = {};
rtDesc.Width = 1920;
rtDesc.Height = 1080;
rtDesc.MipLevels = 1;
rtDesc.ArraySize = 1;
rtDesc.Format = DXGI_FORMAT_R16G16B16A16_FLOAT;
rtDesc.BindFlags = D3D11_BIND_RENDER_TARGET | D3D11_BIND_SHADER_RESOURCE;
rtDesc.SampleDesc.Count = 1;
rtDesc.SampleDesc.Quality = 0;
device->CreateTexture2D(&rtDesc, nullptr, &renderTargetTexture);
```

这里 `D3D11_TEXTURE2D_DESC` 描述的是一张 HDR render target。创建完成后，通常会继续创建 RTV 和 SRV，见 [[rendering/Render-Target]]。

## Image Texture 示例

```cpp
D3D11_TEXTURE2D_DESC imageDesc = {};
imageDesc.Width = image.GetDimensions().x;
imageDesc.Height = image.GetDimensions().y;
imageDesc.MipLevels = 0;
imageDesc.ArraySize = 1;
imageDesc.Format = image.m_isHDR ? DXGI_FORMAT_R32G32B32A32_FLOAT : DXGI_FORMAT_R8G8B8A8_UNORM;
imageDesc.SampleDesc.Count = 1;
imageDesc.SampleDesc.Quality = 0;
imageDesc.Usage = D3D11_USAGE_DEFAULT;
imageDesc.BindFlags = D3D11_BIND_SHADER_RESOURCE | D3D11_BIND_RENDER_TARGET;
imageDesc.CPUAccessFlags = 0;
imageDesc.MiscFlags = D3D11_RESOURCE_MISC_GENERATE_MIPS;
device->CreateTexture2D(&imageDesc, nullptr, &imageTexture);
```

这里 `MipLevels = 0` 和 `D3D11_RESOURCE_MISC_GENERATE_MIPS` 是配套的：D3D11 创建完整 mip chain，GPU 后续可以根据 level 0 自动生成其他 mip levels。

上传 image 像素数据到 level 0 的流程见 [[D3D11.Texture#上传图片数据到 Texture]]。

## Shadow Map 示例

Shadow map 的底层 texture 通常使用 typeless format，因为同一张 texture 既要通过 DSV 写 depth，也要通过 SRV 在 shader 里读 depth。

```cpp
TextureDescriptionConfig shadowDesc;
shadowDesc.width = 2048;
shadowDesc.height = 2048;
shadowDesc.mipLevels = 1;
shadowDesc.arraySize = 1;
shadowDesc.format = DXGI_FORMAT_R24G8_TYPELESS;
shadowDesc.sampleCount = 1;
shadowDesc.sampleQuality = 0;
shadowDesc.usage = D3D11_USAGE_DEFAULT;
shadowDesc.bindFlags = D3D11_BIND_DEPTH_STENCIL | D3D11_BIND_SHADER_RESOURCE;
shadowDesc.cpuAccessFlags = 0;
shadowDesc.miscFlags = 0;
device->CreateTexture2D(&shadowDesc, nullptr, &shadowMapTexture);
```

对应的 view format：

```text
Texture resource = DXGI_FORMAT_R24G8_TYPELESS / 未固定语义的 24+8 bit 存储
DSV              = DXGI_FORMAT_D24_UNORM_S8_UINT / shadow pass 写 depth-stencil
SRV              = DXGI_FORMAT_R24_UNORM_X8_TYPELESS / main pass shader 读 24-bit depth，忽略 8-bit stencil
```

完整解释见 [[rendering/Shadow-Map]]。

## 常见坑

- **没有清零 descriptor**：未填写字段可能保留随机值，导致 `CreateTexture2D` 失败。
- **`BindFlags` 漏写用途**：没有 `D3D11_BIND_SHADER_RESOURCE` 就不能创建 SRV；没有 `D3D11_BIND_RENDER_TARGET` 就不能创建 RTV。
- **`Format` 和 View 不匹配**：texture format 决定后续 RTV / SRV / DSV 能怎么解释它。
- **`MipLevels = 0` 但没配 `GENERATE_MIPS`**：想自动生成 mipmap 时，通常要同时设置 `D3D11_RESOURCE_MISC_GENERATE_MIPS`，并让 texture 支持 SRV + RTV。
- **MSAA 参数不匹配**：同一 render pass 里的 render target 和 depth buffer sample count 要匹配。
- **resize 后忘记重建**：窗口尺寸变化时，依赖窗口大小的 texture descriptor 也要重新生成。

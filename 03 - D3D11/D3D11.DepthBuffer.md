# D3D11 Depth Buffer

一句话直觉：**Depth Buffer 是一张和屏幕一样大的 GPU texture，用来记录每个像素离摄像机有多近**。GPU 渲染时会用它做 Depth Test，让近处物体挡住远处物体。

在 D3D11 里，常见流程是：

1. 用 [[D3D11.D3D11_TEXTURE2D_DESC]] 描述一张 depth-stencil texture。
2. 创建一张 `ID3D11Texture2D` 作为底层 depth-stencil resource。
3. 基于这张 texture 创建 `ID3D11DepthStencilView`。
4. 通过 [[D3D11.OMSetRenderTargets]] 把 Render Target View 和 Depth Stencil View 一起绑定到 Output Merger。
5. 每帧渲染前清空 depth buffer。

---

## 代码在做什么

```cpp
HRESULT              hr;
D3D11_TEXTURE2D_DESC depthTextureDesc = {};
depthTextureDesc.Width                = g_engine->m_window->GetClientDimensions().x;
depthTextureDesc.Height               = g_engine->m_window->GetClientDimensions().y;
depthTextureDesc.MipLevels            = 1;
depthTextureDesc.ArraySize            = 1;
depthTextureDesc.Usage                = D3D11_USAGE_DEFAULT;
depthTextureDesc.Format               = DXGI_FORMAT_D24_UNORM_S8_UINT;
depthTextureDesc.BindFlags            = D3D11_BIND_DEPTH_STENCIL;
depthTextureDesc.SampleDesc.Count     = 1;

hr = m_device->CreateTexture2D(&depthTextureDesc, nullptr, &m_depthStencilTexture);
if (!SUCCEEDED(hr))
{
    ERROR_AND_DIE("Could not create texture for depth stencil.");
}
```

这段代码创建的是 **Depth Stencil Texture**，也就是一张专门给 depth/stencil 测试使用的 `Texture2D`。

它还不能直接被 Output Merger 使用。真正绑定到渲染管线时，通常还需要用它创建一个 `ID3D11DepthStencilView`。

---

## 为什么先清零

```cpp
D3D11_TEXTURE2D_DESC depthTextureDesc = {};
```

[[D3D11.D3D11_TEXTURE2D_DESC]] 是一个 C++ struct。它包含很多字段，但创建 depth buffer 时通常只手动填写其中一部分。

用 `= {}` 初始化的作用是：**把整个 descriptor 的所有字段先变成 0**。这样没手动填写的字段也有确定的默认值，而不是随机内存垃圾值。

例如下面这些字段在当前代码里没有显式填写：

```cpp
depthTextureDesc.CPUAccessFlags;
depthTextureDesc.MiscFlags;
depthTextureDesc.SampleDesc.Quality;
```

如果写成这样：

```cpp
D3D11_TEXTURE2D_DESC depthTextureDesc;
```

这些未填写字段不会自动清零，可能残留随机值。D3D11 可能误以为这张 texture 需要 CPU 访问、有特殊资源标记，或者使用非法的 MSAA quality，最后导致 `CreateTexture2D` 失败。

> [!tip]
> D3D11 descriptor 常见写法都是先清零，再填写自己关心的字段。通用字段说明见 [[D3D11.D3D11_TEXTURE2D_DESC]]。

---

## 字段解释

```cpp
// Match the window client size so each screen pixel has a depth value
depthTextureDesc.Width  = g_engine->m_window->GetClientDimensions().x;
depthTextureDesc.Height = g_engine->m_window->GetClientDimensions().y;

// Depth buffers do not need mipmaps; only the base level is required
depthTextureDesc.MipLevels = 1;

// Create one texture, not a texture array
depthTextureDesc.ArraySize = 1;

// GPU-owned resource; CPU does not directly read or write it
depthTextureDesc.Usage = D3D11_USAGE_DEFAULT;

// 24 bit depth + 8 bit stencil
depthTextureDesc.Format = DXGI_FORMAT_D24_UNORM_S8_UINT;

// Bind this texture as a depth-stencil resource
depthTextureDesc.BindFlags = D3D11_BIND_DEPTH_STENCIL;

// No MSAA
depthTextureDesc.SampleDesc.Count = 1;
```

## `DXGI_FORMAT_D24_UNORM_S8_UINT`

这个格式说明 depth-stencil texture 的**每个像素怎么存数据**：

```text
每个像素 32 bits = 4 bytes
[ Depth: 24 bits ][ Stencil: 8 bits ]
```

它不是普通颜色 texture，不是 `R + G + B + A` 四个颜色值，而是两个逻辑值：

```text
Depth   = 24-bit UNORM
Stencil = 8-bit UINT
```

### 24-bit UNORM

`D24_UNORM` 用在 **depth test**。

```text
D24   = 用 24 bits 存 depth
UNORM = unsigned normalized integer
```

这里的 depth 在内存里不是 float，而是 24-bit unsigned integer。GPU 使用它时，会把整数映射到 `0.0 ~ 1.0` 范围。

```text
0                  -> 0.0
最大 24-bit 整数    -> 1.0
中间值              -> 介于 0.0 和 1.0
```

Depth 的用途是判断前后遮挡：

```text
新的 depth 比 depth buffer 里已有的 depth 更近
-> depth test 通过
-> 允许写入颜色和新的 depth
```

平时渲染 3D 场景时，近处物体挡住远处物体，主要靠这一部分。

### 8-bit UINT

`S8_UINT` 用在 **stencil test**。

```text
S8   = 用 8 bits 存 stencil
UINT = unsigned integer
```

Stencil 不表示远近，它更像是给屏幕像素打整数标签：

```text
stencil = 0  -> 普通区域
stencil = 1  -> 被标记区域
```

后续渲染时可以根据 stencil 值限制绘制区域：

```text
只画 stencil == 1 的地方
不要画 stencil == 0 的地方
```

常见用途：

- 镜子
- 传送门
- UI mask
- 轮廓描边
- 只在某个区域渲染

## Texture 和 View 的关系

`CreateTexture2D` 创建的是底层资源：

```cpp
ID3D11Texture2D* m_depthStencilTexture;
```

但 D3D11 绑定资源时通常绑定的是 View：

```cpp
ID3D11DepthStencilView* m_depthStencilView;
```

常见后续代码：

```cpp
hr = m_device->CreateDepthStencilView(m_depthStencilTexture, nullptr, &m_depthStencilView);
```

可以理解成：

```text
Texture = 真正的 GPU 内存
View    = 告诉 GPU 这块内存这次要怎么用
```

这和 [[D3D11.RenderTargetView]] 的思路一致：Render Target 也是 texture，作为输出目标时需要 RTV。

---

## 绑定到 Output Merger

创建完 Depth Stencil View 后，通常和 Render Target View 一起绑定：

```cpp
m_deviceContext->OMSetRenderTargets(1, &m_mainRenderTargetView, m_depthStencilView);
```

这样 Output Merger 阶段就同时知道：

- 颜色写到哪里：Render Target View
- 深度/模板写到哪里：Depth Stencil View

---

## 每帧清空

每一帧开始画 3D 场景前，一般要清空 depth buffer：

```cpp
m_deviceContext->ClearDepthStencilView(m_depthStencilView, D3D11_CLEAR_DEPTH | D3D11_CLEAR_STENCIL, 1.0f, 0);
```

`1.0f` 通常代表最远深度。清空后，新一帧的物体才能重新参与 depth test。

---

## 常见坑

- **descriptor 没有清零**：`D3D11_TEXTURE2D_DESC depthTextureDesc;` 会留下未初始化字段，可能让 `CreateTexture2D` 因为随机参数组合失败。
- **只创建 Texture 不够**：`CreateTexture2D` 之后还需要 `CreateDepthStencilView`。
- **尺寸要和 Render Target 匹配**：depth buffer 通常要和 backbuffer / render target 一样大。
- **窗口 resize 时要重建**：backbuffer 变大或变小时，depth texture 和 DSV 也要一起释放并重建。
- **MSAA 参数要匹配**：如果 Render Target 使用 MSAA，depth buffer 的 `SampleDesc` 也要匹配。
- **没有绑定 DSV 就不会做正常 depth test**：`OMSetRenderTargets` 的第三个参数不能一直是 `nullptr`。
